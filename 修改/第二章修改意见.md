# 第二章修改意见

本意见仅针对文件 `/Users/miles/Desktop/大论文/BUPTGraduateThesisLatexTemplate/Chapter/Chapter_02_Fundamentals.tex`，聚焦第二章本身存在的不合适、不准确或可改进之处，不涉及其他章节。

## 总体判断

第二章的整体框架已经比较完整，具备“任务场景 -> 传播机理 -> 经典方法 -> 智能方法 -> 性能评估”的清晰链路，作为全文理论基础章是成立的。但当前版本仍存在几类比较实质的问题：

1. 研究对象、信号源和后续建模对象之间的关系没有交代清楚，存在概念层面的混淆风险。
2. “低成本无人机平台”这一题眼在第二章中没有被真正立起来，平台约束与后续方法设计之间的逻辑还不够强。
3. 个别经典方法与本文场景的适配关系没有说透，尤其
4. 是 TDOA 和 PDR。
5. 个别小节虽然公式正确，但仍偏“教材式罗列”，与本文后续方法之间的耦合不够紧。
6. 章节内部有少量重复表述与可压缩内容，会影响成稿的紧凑度。

下面按重要程度列出具体问题。

## 一、需要优先处理的问题

### 1. 研究对象与信号建模对象之间存在潜在混淆

- 位置：
  - 第 10-12 行
  - 第 43 行
  - 第 80 行
  - 第 146-172 行
  - 第 177 行
- 问题说明：
  前文多次把被定位对象表述为“地面非法低轨卫星终端”，并写成“目标终端发射的辐射信号”或“信号从地面发送至无人机”；但后文信号体制建模又切换到 “Starlink Ku 波段下行链路帧结构”。这会让读者产生疑问：本文到底是在利用非法终端自身的上行/辐射信号定位，还是利用卫星下行链路相关信号做特征提取，抑或是利用终端相关的转发/伴生信号进行间接定位？
- 风险：
  这是第二章最关键的概念问题。如果这里不说清楚，后面第三章、第四章里关于 I/Q 建模、射线追踪和观测量来源的合理性都会被削弱。
- 修改建议：
  在第 2.1 节或第 2.2 节开头单独补一段“本文信号建模对象说明”，明确回答以下问题：
  - 被定位对象是谁：非法地面终端还是与其相关的链路活动区域。
  - 被处理的信号是谁发出的：终端上行、卫星下行，还是与终端行为相关的复合观测。
  - 为什么选择 Starlink Ku 波段下行链路作为建模对象，它和非法终端定位任务之间的技术关联是什么。
  如果本文实际上只是借助 Starlink 下行信号做环境感知或特征构造，也建议把“终端辐射信号”改成更中性的说法，如“与目标活动相关的可观测无线信号”。

### 2. “低成本无人机平台”没有被具体化，导致章节标题支撑不足

- 位置：
  - 第 37-71 行
- 问题说明：
  当前第 2.1.2 节写了系统总体架构，但基本停留在抽象数据流层面，没有把“低成本”这个论文题目中的核心约束具体落到平台能力上，例如载荷限制、阵列规模限制、时间同步限制、机载算力限制、航时约束、边缘推理时延约束等。
- 风险：
  后文很多方法选择其实都和“低成本平台”有关，例如为何不走多阵列高精度 AoA、为何不走严格同步 TDOA、为何要做轻量观测与智能融合。如果第二章不先把约束立住，后续方法的工程合理性会显得不足。
- 修改建议：
  建议在第 2.1 节增加一个小节，或在 2.1.2 末尾补一段“低成本平台约束对定位方法设计的影响”，至少写清楚：
  - 为什么不适合依赖大规模阵列和高精度同步硬件。
  - 为什么更适合采用 RSSI、机动多位置观测、学习式融合和图像域判别。
  - 后续方法在复杂度、推理时延、部署可行性上的设计取向。
  如果有实际平台参数，哪怕只给出量级，也会比纯抽象表述更有说服力。

### 3. TDOA/TOA 的建模场景与本文平台设定之间衔接不够

- 位置：
  - 第 246-268 行
- 问题说明：
  TOA 和 TDOA 小节当前采用的是标准“多接收机”表述，特别是 TDOA 直接写成“第 i 个接收机和参考接收机 1”。但第二章前文主叙事是“低成本无人机机动观测平台”，容易让人疑惑这些多接收机到底对应什么：
  - 多架无人机协同？
  - 单架无人机多时刻观测形成的虚拟多站？
  - 地面辅助站与无人机联合？
- 风险：  
  如果不补充说明，第二章会给人一种“经典方法照搬进来，但和本文系统不完全对应”的感觉。
- 修改建议：
  在 TOA/TDOA 小节末尾增加一句到一段“与本文场景的对应关系说明”，明确：
  - 这些模型在本章中主要作为理论参考和经典基线。
  - 若映射到本文场景，需要附加哪些条件，如多节点同步、目标近似静止、航迹配准等。
  - 为什么这些条件在低成本无人机场景下难以长期满足。
  这样就能把“理论基础”与“本文不直接采用的原因”交代完整。

### 4. PDR 的使用与“非法终端非合作定位”之间存在明显概念跳跃

- 位置：
  - 第 277-285 行
- 问题说明：
  PDR 是典型的行人惯导递推模型，默认需要步长、航向等运动学信息，通常来自目标自身的 IMU 或可观测运动先验。但本文研究对象是“非法低轨卫星终端”的非合作定位，第二章没有说明 PDR 的信息来源是什么，也没有解释 PDR 是作用于目标轨迹、无人机自身轨迹，还是作为后端平滑先验引入。
- 风险：
  这是第二章里另一个比较重的逻辑问题。若不解释，读者会质疑后续融合框架里为何能合法、合理地使用 PDR。
- 修改建议：
  需要二选一：
  - 如果后文的 PDR 实际上是“目标运动轨迹先验/轨迹递推模块”的简化称呼，建议在第二章改名或改写，避免直接使用 Pedestrian Dead Reckoning 这一强场景词。
  - 如果确实使用 PDR，请明确数据来源，例如地面协同传感器、目标侧可获取惯性信息、或仿真设定中的辅助运动先验。
  至少要在第二章先把“PDR 为什么能出现”讲明白，否则会影响第三章方法的可信度。

## 二、建议加强的问题

### 5. Starlink 小节过于“通用 OFDM 化”，对全文支撑力度不够

- 位置：
  - 第 146-172 行
- 问题说明：
  当前这一小节虽然标题是“Starlink Ku 波段下行链路帧结构”，但正文只给出了非常通用的 OFDM 基本表达式和循环前缀时长关系，没有进一步交代：
  - 选择 Starlink 的原因；
  - 该建模与后续 I/Q 样本、射线追踪、特征提取之间的具体关系；
  - 这里到底是在做“真实协议近似建模”还是“仅保留定位相关结构的抽象建模”。
- 风险：
  标题给人的预期是“有一定 Starlink 特定性”，正文实际却更像“通用 OFDM 复习”，容易产生标题与内容不匹配的问题。
- 修改建议：
  可考虑以下两种改法之一：
  - 保留标题，但补充 1-2 段“为什么本文只保留与定位特征相关的关键结构，不追求完整协议复现”的说明。
  - 如果本节实际只需要一个可用于后续样本生成的 OFDM 基带模型，则建议把标题改得更稳，例如“面向后续信号建模的 Starlink 下行链路抽象表示”。
  若能补上与参考文献一致的具体参数或明确说明“本文不依赖具体协议参数，只保留 OFDM 结构特征”，会更严谨。

### 6. 第二章中若干表述是“教材式总结”，与后续章节的映射还可以更紧

- 位置：
  - 第 303-404 行
  - 第 409-429 行
  - 第 505-555 行
- 问题说明：
  MDP、DQN、知识蒸馏、CRLB 的基本定义都没有明显错误，但仍有偏“标准理论介绍”的问题，与本文具体任务的绑定不够深。比如：
  - MDP 小节已经开始结合后文，但还可以更明确地把状态、动作、奖励分别对应到本文变量。
  - DQN 小节没有点出本文后续其实还存在动作设计受权重归一化约束的特点。
  - CRLB 小节没有强调它主要适用于经典观测模型，不宜直接拿来评价深度学习或蒸馏模型的性能上界。
- 修改建议：
  第二章不需要展开到和正文重复，但建议每个理论小节结尾都增加一句“本文中的具体对应关系/适用边界”，例如：
  - MDP 中状态对应物理感知特征，动作对应融合权重调整。
  - DQN 是后续 PA-DQN 的基础，但后续还引入了物理先验与特定动作约束。
  - CRLB 主要为 RSSI/AoA/TOA/TDOA 这类参数化观测模型提供理想参考，不直接代表学习模型的性能上界。

## 三、成稿层面的可优化点

### 7. 路径损耗公式在第二章内重复出现，可适当压缩

- 位置：
  - 第 130-143 行
  - 第 184-205 行
- 问题说明：
  对数距离路径损耗模型在 2.2 节和 RSSI 小节中各写了一遍，内容高度重复。单独看没有错误，但会让第二章略显松散。
- 修改建议：
  建议保留其中一处完整推导，另一处改成“由式 xx 可知”并直接承接 RSSI 测距公式或几何约束，这样章节会更紧凑。

### 8. 第 2.4 节开头存在轻微重复表达

- 位置：
  - 第 296-298 行
- 问题说明：
  “后续研究需要引入能够适应复杂状态变化的数据驱动方法与智能学习机制”这一层意思在相邻两段中重复出现，阅读上略拖沓。
- 修改建议：
  合并成一段即可，保留“为什么要引入智能方法”和“本节具体介绍哪些理论基础”两个层次即可。

### 9. 第二章对“适用边界”的强调还可以再更主动一些

- 位置：
  - 全章，尤其是经典定位方法和 CRLB 部分
- 问题说明：
  当前第二章总体上是在为后文服务，但不少地方还是“给出模型后再说局限”。从答辩或盲审阅读体验看，如果能更主动地强调“哪些模型是理论基线、哪些条件在本文场景下并不成立”，说服力会更强。
- 修改建议：
  可在每个经典方法小节结尾统一用一句模式化表达：
  - “因此，该方法在本文中主要作为理论参考/基线方法，其直接工程适用性受限于……”
  这样第二章会更像“为本文研究问题筛选方法基础”，而不是简单的定位教材综述。

## 建议的修改顺序

建议按下面顺序处理第二章：

1. 先解决“研究对象-信号源-建模对象”关系不清的问题。
2. 再补“低成本平台约束”与“PDR 来源说明”。
3. 之后修正 TOA/TDOA 与本文平台之间的适配说明。
4. 再加强 Starlink 小节与后续章节之间的耦合叙述。
5. 最后做重复压缩和语言收紧。

## 一句话结论

第二章目前最大的问题不是公式错，而是“概念边界还不够锐利”。只要把信号来源、平台约束、PDR 合法性和经典方法适用边界这几个点补实，第二章会从“写得完整”提升到“写得扎实、能经得住追问”。
